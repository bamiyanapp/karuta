# backend/seed.jsの冪等性・データ整合の設計方針

`backend/seed.js`は、CSV（`backend/phrases.csv`）の内容をDynamoDBテーブル（`karuta-phrases`）へ同期するスクリプトである。CDワークフローは`main`へのマージごとに本スクリプトを実行し、CSVの全件を毎回同期する。このため、本スクリプトは**何度実行しても結果が同じになる（冪等である）**必要がある。

本ドキュメントは、この冪等性・データ整合を成立させるための設計意図を記録する。実装の詳細（コード自体）は`backend/seed.js`を参照し、本ドキュメントでは「なぜそうしているか」のみを記す。

## 統計情報（readCount等）の引き継ぎ

CDは`main`へのマージごとに毎回全件同期を実行するため、単純にCSVの内容でDynamoDBを上書きすると、読み上げ回数・平均難易度等のユーザー操作で蓄積された統計情報が、デプロイのたびにリセットされてしまう。

これを防ぐため、`seed.js`は同期前に既存のDynamoDB項目を取得し、新規レコード（既存項目が無い場合）のみ統計を0で初期化する。既存レコードの統計は、CSV側の内容（phrase・answer等）が変わっても上書きせずそのまま引き継ぐ。

## カテゴリ名変更時の統計引き継ぎ（`CATEGORY_RENAMES`）

`karuta-phrases`テーブルは`category`をパーティションキーの一部として使う。このため、CSV上でカテゴリ名を変更すると、DynamoDB上は全く別のレコードとして扱われ、上記の統計引き継ぎが機能しない（旧カテゴリ名の統計が宙に浮き、新カテゴリ名側は新規レコードとして統計がリセットされる）。

この制約に対応するため、`seed.js`に`CATEGORY_RENAMES`マップ（変更後のカテゴリ名→過去に使っていたカテゴリ名の配列）を持たせている。**カテゴリ名を変更するPRでは、必ずこのマップへ追記する**。追記を忘れると、そのカテゴリの統計情報が失われる。

## CSVから削除されたアイテムの扱い

CSVから行を削除すると、対応するDynamoDB項目も削除される（`DeleteCommand`）。CSVを「現在のかるた全件の正」として扱う設計であり、CSVに存在しない項目をDynamoDB側に残さない。

このため、統計情報を保持したまま一時的にカテゴリを非表示にしたい場合等、削除ではなく別の手段（別ブランチで保持する等）を検討する必要がある。誤って削除してしまった場合の復旧手段は、[DynamoDBオンデマンドバックアップ・復旧手順](data-backup-restore.md)およびPoint-in-Time Recovery（[README.md](../README.md)「バックアップと復旧」参照）を使う。
