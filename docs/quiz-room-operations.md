# クイズ大会モード 運用手順

本ドキュメントは、クイズ大会モード（README.md「Features」参照）を実際に運営する際の正常系・異常系の挙動と、対応する自動テスト・手動確認手順を整理したものである（issue #640）。

## 正常系: 基本的な利用の流れ

1. **管理者**: division選択（こども向け/エンジニア向け）→ かるたの種類を選択 → ゲーム画面下部の「クイズ大会のルームを作成する」を押す
2. 「ルーム情報を表示（クイズ大会モード）」からルームコード・QRコード・招待URLを確認し、参加者へ共有する
3. **参加者**: QRコード/招待URLから直接参加するか、トップページの「他のクイズ大会に参加する」からルームコードを入力して参加し、表示名を入力する
4. 管理者が「次の札」を押すと、読み札・音声が参加者側にもリアルタイムに同期される
5. 早押し（回答するボタン）→ 管理者が正誤を判定（判定時に効果音が管理者・参加者双方で再生される） → 正解時はポイントが加算される
6. 複数回戦を行う場合、管理者はルーム情報画面の「ポイントをリセット」で参加者全員のポイントを0に戻せる（次のカテゴリ選択・進行はリセットされない、明示操作でのみリセットされる）

## 異常系・既知の制約

### 管理者のセッション断（ページのリロード・タブのクラッシュ・PWAの再起動等）

- **現状の挙動**: 管理者トークン（`adminToken`）はReact stateにのみ保持され、`localStorage`等に永続化されていない（`frontend/src/hooks/useQuizRoomAdmin.js`）。division・かるたの種類の選択はURLクエリパラメータ経由で復元されるためゲーム画面自体には戻るが、ルームとの紐付け自体は失われ、「クイズ大会のルームを作成する」ボタンが再度表示される。**同じルームへ管理者として復帰する手段は無い**
- **参加者への影響**: 何の通知も届かない。それまでの画面（読み札表示・「ホストの操作を待っています...」等）のまま変化しない
- **運営者が取るべき代替手順**: 新しいルームを作り直し、参加者へQRコード/URL/ルームコードを改めて手動で共有する。新ルームは開設中ルーム一覧の先頭（作成日時降順）に表示されるため、参加者は一覧から選び直すこともできるが、失効前の旧ルームも一覧に残り続け見分けが付かないため、どのルームが新しいかを口頭等で明示的に案内するのが安全
- 回帰テスト: `frontend/e2e/quiz-room.spec.js`（issue #640で追加、現状の挙動をそのまま固定化）
- 関連: issue #640（本調査）、issue #617（ルーム終了・一覧の絞り込み、未対応）

### 参加者・管理者のセッション断（画面ロック・バックグラウンド復帰）

- スマホの画面ロックやアプリのバックグラウンド化でWebSocketが切断されても、フォアグラウンド復帰時に自動的に再接続される。自動再接続の上限に達した場合は画面に表示される「再接続」ボタンから手動で再接続できる（issue #614で対応済み）
- 管理者側にも接続状態（接続中/切断済み等）が表示される

### 誤ったルームコード・失効済みルームでの参加

- **現状の挙動**: 存在しない、または既に失効したルームコードを入力すると、約15秒間の接続リトライの後に「接続できませんでした」とだけ表示される。ルームコードの誤りなのかネットワーク障害なのかを区別できない
- **未対応**: issue #616

### ルームの終了・放置ルームの扱い

- **現状の挙動**: 管理者がルームを明示的に終了する手段が無い。放棄されたルームはDynamoDBのTTL（24時間）で自動失効するまで開設中ルーム一覧に残り続ける
- **未対応**: issue #617（対応方針として、管理者接続の無いルームを一覧から除外する「絞り込み」のみを軽量な対応として採用予定だが、未実装）

### 開設中ルーム一覧の鮮度

- トップページを開いたまま放置していても、15秒間隔の定期ポーリングと、タブ/アプリのフォアグラウンド復帰時（`visibilitychange`）の即時再取得により、他の管理者が新しく開設したルームが自動的に一覧へ反映される（issue #640で対応済み）

## 手動確認用チェックリスト（自動化しにくいシナリオ）

複数の実端末・実ネットワークの状態変化が絡むシナリオはE2Eでの自動化が難しいため、大会本番前に手動で確認することを推奨する。スマートフォンオンリーの運用前提（`dev-standards`のCLAUDE.md「開発環境の制約（スマホオンリー）」参照）に沿い、いずれもスマートフォンのブラウザ操作のみで確認できる内容にしている。

- [ ] 管理者端末の画面をロック→数十秒後に復帰し、進行操作（次の札・判定）が問題なく続けられること
- [ ] 参加者端末を複数台用意し、ほぼ同時に早押しした場合に最初の1件だけが確定し、他の端末には「〇〇さんが回答中」と表示されること
- [ ] 管理者が意図的にタブ/アプリを閉じて新しいルームを作り直した場合、既存の参加者側の画面が変化しないこと（上記「管理者のセッション断」の実機確認）と、新ルームへの再参加手順
- [ ] Wi-Fi/モバイル回線を実際にオフにしてから再度オンにし、参加者・管理者双方が自動的に再接続されること
- [ ] 回答ボタン・正解・不正解の効果音が、管理者・参加者双方の実機で実際に鳴ること
